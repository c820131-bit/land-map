# INVESTMENT MAP — 프로젝트 최상위 지침 (PROJECT_CHARTER)

> 이 문서는 모든 Claude 작업창(A·B·C·D·E·H)이 인계받을 때 가장 먼저 읽는 문서다.
> 사용자 지침(2026-11-08 "자동 인계·연속 개발 시스템 구축 지침")을 근거로 작성했으며,
> **사용자 결정(DECISIONS)을 대신하지 않는다.** 사용자 결정은 `state/decisions.json` 에만 기록되며 수정·삭제할 수 없다.

## 1. 만들려는 것
실제 **경매물건을 클릭**하면 다음을 한 화면에서 확인하는 투자지도:
보상사업 편입관계 · 공식 고시 · 법적 단계 · 토지조서 · 권리별 면적 · 도면 · 타임라인 · 인근 낙찰 및 보상사례 · 투자분석.

## 2. 담당 창(역할)
| 역할 | 담당 | 비고 |
|---|---|---|
| A | 공식 공고·첨부·출처·사업 구간·정정·취소·증분 수집 | 출처 계약 → B |
| B | PDF·HWP·HWPX·XLSX 토지조서 판독·지번·권리·면적·원문 위치 | 판독본 → C |
| C | 경매물건 연결·지도·API·보상사업 패널·공식 원문·거리 검색 | 후보 → D |
| D | 독립 검수·공식 원문 대조·보상사례 및 투자분석 | **유일한 독립 검수(reviewer) 권한** |
| E | 업무관리 브라우저 개선, 별도 검증 또는 명시된 담당 업무 | 업무관리 브라우저 UI 변경 금지(13절) |
| H | 공통 인계 저장소·복원 도구·시험 | A~E 작업 침범 금지 |

담당 창을 지정받지 않은 새 창은 **어떤 역할도 점유하지 않는다** (`status` 로 조회만 하고 사용자에게 확인 요청).

- 사용자 승인 없는 배포
- 기존 업무관리 브라우저 UI 및 버튼 변경

## 5. 최신 상태 판단 규칙
"최신 개발 후보"와 "마지막 정상 합격판"은 **항상 분리**해서 다룬다.
- 후보는 등록 시점의 SHA-256 으로 고정된다. 고정 후 파일이 바뀌면 같은 후보가 아니다 → 새 후보로 등록.
- 합격판은 D 가 `review --status pass` 로 기록하고, 검수된 SHA 와 현재 파일 SHA 가 일치할 때만 `set-passed` 할 수 있다.
- D 가 `hold`(보류)한 후보는 어떤 창에서도 합격판이 될 수 없다.
- 자체 시험(`self-test`)과 독립 검수(`review`)는 다른 기록이다.
- 운영 반영(`deployed`)·사용자 승인(`user_approved`)은 별도 필드이며, 사용자 승인은 `--user-approved` 플래그가 있을 때만 기록된다.

## 6. 작업 규칙
- 상태를 바꾸려면 먼저 `takeover <역할>` 로 임대를 받아야 한다. 임대는 세션 단위이며 TTL(기본 1시간) 안에 `heartbeat` 가 없으면 만료된다.
- 완료 승격(`task complete`)에는 반드시 `--evidence` 가 필요하다.
- `requires_user_approval` 작업은 사용자 결정(`decision add --user-approved --approves-task`)이 있을 때만 시작할 수 있다. 배포·운영 변경은 모두 여기에 해당한다.
- 작업을 끝내거나 창을 옮길 때는 `checkpoint <역할> --file ... --next-command ... --release` 로 기록하고 임대를 해제한다.
- 모든 오류는 `error add` 로 기록한다(ID·근거·재현·기대/실제·원인·수정 파일 SHA·검증·미해결 사유·재개 조건).

## 7. 접근 범위 — 실제 확인된 것 / 미확인
### 확인됨 (2026-11-08, 클라우드 Claude Code 세션)
- 이 저장소 `c820131-bit/land-map` 에는 A·B·C·D·E 작업 폴더, 기존 인계 스크립트, `DECISIONS`, `CHATGPT_WORK_BRIEF.md` 가 **존재하지 않는다**. 루트에는 운영 정적 지도(index.html, data_*.json, netlify 함수)만 있다.
- 사용자 PC 폴더 `C:\클로드\보상개발지도` 는 클라우드 세션에서 **접근 불가**(Remote Control 공유 폴더 목록에 없음).
- Claude 창들은 서로의 대화를 자동 공유하지 않는다. 이 세션은 다른 창의 대화·상태를 볼 수 없다. 따라서 인계는 **파일·체크포인트 기반**(`_HANDOFF/state/**`)으로만 이루어진다.
- Claude Code(CLI·웹·클라우드 세션)는 저장소 루트의 `CLAUDE.md` 를 세션 시작 시 자동으로 읽는다. 이 저장소의 `CLAUDE.md` 가 "INVESTMENT MAP X 인계받고 이어서 작업해" 문장을 `handoff.py takeover X` 실행으로 연결한다.
### 미확인 (사용자 확인 필요)
- claude.ai **프로젝트 지침/프로젝트 지식 파일**이 새 대화창에 자동 제공되는지, 그리고 그 창이 로컬 파일을 실행할 수 있는지. 지원된다면 `_HANDOFF/START_PROMPT.md` 내용을 프로젝트 지침에 붙여 넣는다. 지원 여부와 무관하게 사용자는 새 창에서 아래 한 문장만 입력하면 된다.
